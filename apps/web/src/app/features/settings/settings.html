Architecture Notes

How this system is designed to handle scale and production concerns.

State & Caching

Components use Angular signals with ChangeDetectionStrategy.OnPush — only re-render on explicit signal writes. Shared state (campaign, donations) lives in root-level services using httpResource, which caches the last response and avoids duplicate requests across components. Health data uses shareReplay(1) so the health and spike services share one HTTP stream.

Performance at Scale

All donation queries are server-side paginated (max 100 rows per page) with DB indexes on campaign_id + date, donor_id, channel, and is_mock. The donations list never loads a full table scan. Mock data stress-tests this: generate 5,000+ rows and pagination stays fast.

Real-time Updates

A WebSocket at /api/donations/live pushes new donations instantly to all connected clients — no polling needed for the live feed. Mutations (POST donation) re-fetch via the WebSocket event rather than an additional HTTP call. This page uses 5-second polling for health since WebSocket push isn't suitable for infrastructure metrics.

Production Readiness

Auth is enforced at the API level (better-auth sessions) and via Angular route guards. Session lookups are cached in Redis via secondaryStorage — zero Postgres hits per request after first login. Error boundaries handled by a global HTTP interceptor with toast feedback. Spike detection uses Redis SET NX EX for distributed debouncing that survives restarts and scales across replicas.
